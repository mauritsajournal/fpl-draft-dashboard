## 1. Executive Summary

This project aims to build a free, statically hosted dashboard for a Draft Fantasy Premier League (FPL) head-to-head league ("FC Driegangendiner", league ID 820, 8 teams). The dashboard will visualize league data including standings, head-to-head comparisons, player statistics, power rankings, gameweek trends, and puntenvoorspellingen (point predictions) — comparable to commercial tools like DraftFC and FantasyFooty but entirely free and self-hosted on GitHub Pages.

The FPL Draft API at `draft.premierleague.com/api/` provides rich, unauthenticated endpoints covering league details, match results, player ownership, team picks, live event stats, draft choices, and transactions. However, the API enforces a CORS policy that blocks direct browser-to-API requests. This is the single biggest architectural constraint: a static site on GitHub Pages cannot call the API directly from JavaScript. The recommended solution is a **GitHub Actions scheduled workflow** that fetches data server-side and commits JSON files to the repository, which the static site then reads as local files. This approach is completely free (public repo = unlimited Actions minutes) and requires zero ongoing user input.

Research into the competitive landscape reveals two notable commercial products (DraftFC at GBP 3.99/month and FantasyFooty with freemium model) but no open-source equivalent for FPL Draft specifically. This creates an opportunity to build something unique with zero cost by leveraging GitHub's free infrastructure.

### 3.3 Key Insights

1. **No open-source FPL Draft dashboard exists** — there is a genuine gap. All existing tools are either commercial (DraftFC, FantasyFooty) or target regular FPL.
2. **The CORS problem is universal** — every project that touches the FPL API has to solve this. The open-fpl project uses a build-time data fetch pattern, which validates our GitHub Actions approach.
3. **Feature inspiration from FantasyFooty** — their "what-if" fixture analysis and "luck factor" are unique differentiators that would be relatively simple to implement with the data we have.
4. **The Draft API is well-structured** — verified endpoints provide everything needed: league details, matches, picks, live stats, element status, transactions, and draft choices.
5. **8-team league is small enough** that all data can be fetched and stored as JSON without any size concerns.

## 7. Recommendations

### Architecture: GitHub Actions Data Pipeline + Astro Static Site

**Decision:** Use GitHub Actions as a scheduled data fetcher that commits JSON files to the repository. Astro builds a static site from those JSON files and deploys to GitHub Pages.

**Why this over alternatives:**
- **Cloudflare Worker proxy:** Would work but adds a dependency outside GitHub, requires Cloudflare account setup (user input needed), and the Worker would need to handle all API calls in real-time. The GH Actions approach is simpler and more robust.
- **Client-side with CORS proxy:** Fragile, depends on third-party CORS proxy services that are unreliable and often go offline.
- **Server-side rendering (Next.js/Nuxt on Vercel):** Overkill. Adds a server runtime, framework complexity, and a Vercel dependency — all for a dashboard serving 8 people.

**Why Astro over other frameworks:**
- Zero JavaScript by default means fast page loads
- Built-in static site generation is the primary use case
- Official GitHub Pages deployment support
- Svelte islands give interactivity exactly where needed (charts, filters) without shipping a full SPA framework
- Simple learning curve for the engineer agent

**Data refresh strategy:**
- GitHub Actions cron: runs every 6 hours during season (4x/day)
- During live gameweeks: can be manually triggered for real-time updates
- Fetches all endpoints, transforms data into dashboard-ready JSON structures
- Commits only if data has changed (avoids noise in git history)

**Single-league focus:**
- Hardcode league ID 820. No need for a league selector, auth flow, or multi-tenancy.
- This keeps the codebase simple and the dashboard fast.
