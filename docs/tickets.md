- [ ] `scripts/fetch-all.ts` orchestrates all fetches in sequence with 500ms delays between endpoints
- [ ] `data/meta.json` is created/updated with lastFetchedGameweek, lastUpdated, draftFetched
- [ ] Exponential backoff: 3 retries with 2s, 8s, 32s delays
- [ ] API responses are validated (HTTP 200 + expected JSON keys) before writing to disk
- [ ] Failed fetches do NOT overwrite existing data files
- [ ] All scripts are runnable via `npx tsx scripts/fetch-all.ts`

**Technical notes:**
Use Node.js built-in `fetch()` (Node 22). No external HTTP libraries needed.

League ID: 820. Entry IDs for the 8 managers must be read from `data/league.json` (league_entries array), not hardcoded. The initial run will need to fetch league.json first to get entry IDs, then fetch picks/live for all completed GWs.

For the initial seed (GW1-29): 232 pick requests + 29 live requests = 261 requests total. With rate limiting: ~5 minutes. GitHub Actions has a 6-hour timeout, so this is fine.

Batch picks fetch pattern:
```typescript
for (const gw of newGameweeks) {
  const gwPicks = {};
  for (const entry of leagueEntries) {
    await delay(200);
    gwPicks[entry.entry_id] = await fetchWithRetry(`/api/entry/${entry.entry_id}/event/${gw}`);
  }
  writeJson(`data/picks/gw${String(gw).padStart(2, '0')}.json`, gwPicks);
  await delay(1000); // delay between GWs
}
```

> DONE 2026-03-12 — Full transform pipeline producing dashboard.json with all sections. Tested against live data.

**Phase:** 1 (MVP)
**Component:** Data Pipeline
**Depends on:** T-004
**Estimated effort:** XL
**Priority:** P0 (critical path)

**Description:**
Implement the transform script that reads all raw JSON data files and produces `data/dashboard.json` — a pre-computed data structure optimized for dashboard rendering. This is the core business logic of the project.

**Acceptance criteria:**
- [ ] `scripts/transform.ts` reads all data files and produces `data/dashboard.json`
- [ ] Validates file existence and freshness before processing
- [ ] Sets `dataAvailable` flags per section — missing non-critical data produces degraded output, not failure
- [ ] If critical files (league.json, players.json) are missing, exits with error code 1
- [ ] Computes `standings` from league.json matches and standings data
- [ ] Computes `managers` with aggregated stats: total points, average per GW, best GW, worst GW, current form
- [ ] Computes `gameweekHistory` — snapshot of standings after each completed GW for trend charts
- [ ] Computes `h2hMatrix` — 8x8 matrix of all head-to-head records between managers
- [ ] Computes `playerStats` — top players owned in the league with per-GW breakdown
- [ ] Computes `freeAgents` — best unowned players by total_points, form, xG+xA
- [ ] Computes `powerRankings` — team strength score based on player form, xG, total points
- [ ] Processes `transactions` into a structured timeline with player names resolved
- [ ] Processes `draftPicks` with player names resolved
- [ ] Computes `predictions` — next GW expected points per team based on player xG/xA and fixture difficulty
- [ ] Computes `benchAnalysis` — total bench player points per manager per GW (simple version)
- [ ] Records `fetchErrors` from last fetch cycle
- [ ] All computations have unit tests (see T-007)

**Technical notes:**
Player name resolution: join element IDs from picks/transactions/draft with players.json to get `web_name`.

Power ranking algorithm suggestion: weighted sum of (player form * 0.3 + player xGI per 90 * 0.3 + total points * 0.2 + fixture difficulty * 0.2). Normalize to 0-100 scale.

Prediction algorithm: for each player in a team's starting XI, calculate expected points based on: position-specific baseline + xG-based goal probability + xA-based assist probability + clean sheet probability (from fixture difficulty). This is a rough heuristic, not a model.
